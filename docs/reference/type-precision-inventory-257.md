# The final strict-mypy error list (#257)

**What this file is:** the closing inventory for the type-cleanup track (#222,
ticket #257). It states what the raw strict mypy report said when the ticket
started, which findings this batch cleared, what is left (nothing), how the
remaining `dict[str, Any]` / `cast(Any, ...)` / local `type: ignore` uses are
justified, and which typing work is still owed. It exists so the decision about
retiring `mypy-baseline.txt` can be made from facts instead of a count that
moved in the meantime.

**What it is not:** proof of live Maya behaviour. No Maya session was run for
this batch. The behaviour evidence is the fake-Maya test layer and the existing
tool-contract tests, which prove the calls match the fake, not the real command.
Any claim that would need a real interpreter is labelled `human_verify` below.

**Measured environment:** `mypy==2.3.1` (compiled) and `types-maya-strict` from
the repo's uv-managed venv, Python 3.10 target, run as `mypy src`. Ticket start
point `554e1c87` (origin/main when the ticket opened); the work was rebased onto
`fbb9c475` when the #269 merge arrived.

## Three groups the spec asks for

**Safe to clear, cleared:** the ten findings above, plus the aesthetic payload
types that replaced `list[dict[str, Any]]` (objects, lights, materials, zone
records, the five dimension scores, `SHOT_TYPES`).

**Kept on purpose, with a reason in code:**

- Four `type: ignore[call-overload]` lines (camera aim constraints, key tangents,
  playback range). Each names the narrower code and the reason: the stub wants a
  tuple where the call passes a list, or the flag spelling the stub does not
  declare. None is a blanket ignore.
- Three `cast(Any, cmds.xform)` calls. The stub types `xform` so that
  `q=True, t=True` does not return the list the code unpacks. Replacing the cast
  with a precise annotation needs one real Maya session to confirm the return
  shape — `human_verify`.
- `dimensions: dict[str, Any]` in `_compute_full_aesthetic_score`. This merge
  container stays loose on purpose: mypy refuses to assign the narrower
  dimension TypedDicts into a wider optional-key TypedDict (measured: five
  errors), so tightening it needs a full result type for the merge, which is
  follow-up work, not this batch.
- The four `_analyze_*` research helpers now each carry their own result type.
  They differ from each other, not from one shared shape: one returns
  `{avg_clarity, details}`, the others return a score plus either a
  `detail` reason or their extra numbers, so each type says `detail` is
  optional and nothing else is invented.

**Needs a real machine to go further:** only the `cast(Any, cmds.xform)` trio.

## What the types check, and what they do not

The payload types catch a wrong **field name** and a wrong place that reads it;
they do not make the values themselves safer. Most payload values come from
`cmds.getAttr` or the `xform` cast and arrive as `Any`, so a field declared
`float` is only as precise as its source. That is the honest limit of this
batch: the shape is now written down, the value provenance still starts at the
Maya stub boundary.

## `dict[str, Any]`, `cast`, and ignores: the measured shape

52 `dict[str, Any]` occurrences sat in the module before this batch, and 52 sit
there now: the pass removed a few (the `_Objs` alias, the zone-map chain) and
the new payload types added a few of their own, so the count alone says nothing.
What matters is which clusters remain. Most are the JSON envelopes of public
scene tools, which are the documented MCP surface and are pinned by tests in
`tests/test_scene_tools_json.py`; typing each envelope is a per-tool decision,
not a batch. The clusters that are real typing debt are listed under follow-up
below.

## What the pass found that the types had hidden

- `create_camera_shot`'s `angle` is a dict of azimuth/elevation; the docstring
  and the host caller both say so. The first annotation attempt said list and
  mypy rejected the body's `.get` calls, which is the annotation doing its job.
- Object payloads really do carry no colour and no material when the object has
  no shader assignment, so both fields are optional.
- Zone and composition weights started at int zero and received float weights;
  they now start at float zero. Same values.
- `_score_visual_flow` accepted a `zone_map` argument and never read it. The
  only producer of that argument existed to feed it, so the dead path is gone
  and `get_zone_map()` is no longer called from the aesthetic engine. The
  function itself stays; scene checks and constraints still use it. This is the
  one deletion in a typing batch, named here so the pull request body can carry
  it: the output of `analyze_aesthetics` is unchanged, the removed call only
  read Maya state and threw the answer away.

## Follow-up work, grouped by call chain

These are candidate issues for the tracker, not a live register: this file is a
point-in-time record, and an open item belongs in GitHub once someone files it.

1. Aesthetic merge result: give `_compute_full_aesthetic_score` a typed result
   and decide the optional-key merge model, so downstream `score` /
   `sub_scores` / `detail` reads are checked. Shortest route: settle the shape
   of one merged dimension in a small typing-only PR, since the blocker is that
   decision, not Maya behaviour.
2. Duplicated light-payload builders: `analyze_aesthetics` and the scene review
   lighting check build the same dict twice; one helper would serve both.
   Shortest route: extract the builder into `scene_module_types`-adjacent host
   code or a new injected module, because `maya_scene_module.py` is at its cap.
3. `cast(Any, cmds.xform)` trio: needs a real Maya session to record the return
   shape first (`human_verify`), then a typed wrapper. Shortest route: one
   `human_verify` probe recording what `xform(q=True, ws=True, t=True)` returns,
   then replace the three casts with one helper.
4. Tool JSON envelopes: type one tool's envelope at a time, with its contract
   test, rather than in a single sweep. Shortest route: start with
   `get_scene_graph`, whose output test already pins the keys.
5. Smaller shapes the pass left alone, each a separate judgement call:
   `angle` is really a two-field record (azimuth, elevation), the lighting layer
   names are bare strings repeated in three places, `_Bounds` is still
   `dict[str, list[float]]` where the zone boxes already have named fields, and
   `ZoneCore`/`ZoneRecord` mirror `spatial_types.ZoneInfo` as dicts because the
   payload crosses into Maya as JSON. None of these blocks the gate; all four
   would be caught only by a reviewer or a later typo. Shortest route: fold each
   into whichever of 1-4 next touches that code.
